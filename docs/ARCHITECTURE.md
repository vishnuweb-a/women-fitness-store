# Architecture

A client-rendered React single-page application built with Vite. There is no
backend in this repository; Supabase is the intended data layer.

## Stack

| Concern | Choice | Notes |
|---|---|---|
| Language | JavaScript + JSX | No TypeScript. `jsconfig.json` provides editor path resolution only. |
| Build | Vite 8 | `@vitejs/plugin-react` |
| Styling | Tailwind CSS v4 | `@tailwindcss/vite`; CSS-first config, **no `tailwind.config.js`** |
| Components | shadcn/ui | `components.json` with `"tsx": false` → generates `.jsx` |
| Animation | `motion` | Imported as `motion/react` (the library formerly named `framer-motion`) |
| Routing | React Router 7 | `createBrowserRouter` |
| Server state | TanStack Query 5 | |
| Forms | React Hook Form + Zod 4 | via `@hookform/resolvers` |
| Icons | `lucide-react` | |
| Backend | Supabase | Browser client uses the publishable key only |
| Media | Cloudinary | Delivery URLs only; no SDK in the browser |
| Linting | ESLint 9 (flat config) | with `react`, `react-hooks`, `react-refresh`, `jsx-a11y` |

ESLint is pinned to 9.x because `eslint-plugin-jsx-a11y@6.10.2` does not yet
support ESLint 10. Accessibility linting was judged more valuable than the
newer major. Revisit when the plugin adds support.

## Directory layout

```
src/
  app/            App.jsx, router.jsx, providers.jsx — composition root
  components/
    ui/           shadcn/ui primitives (generated; edit in place to customise)
    layout/       site-header, site-footer, root-layout
    shared/       cross-feature pieces: states, error boundary, page shell
  features/       one folder per storefront domain
    home/ collections/ catalog/ product/ cart/ checkout/ account/ orders/
  hooks/          shared custom hooks
  lib/            env, supabase, cloudinary, query-client, utils
  services/       data access — Supabase queries live here, not in components
  data/           static/seed data and constants
  styles/         globals.css (tokens, base layer, custom utilities)
  main.jsx        entry point

public/assets/banners/   runtime copies of the banner art
banners/                 ORIGINAL artwork — preserve, never edit
pages/                   visual references — not route components
docs/                    this documentation
```

### Boundaries

- **`features/`** owns screens and screen-specific components. A feature must
  not import from another feature's internals; promote anything shared to
  `components/shared/`.
- **`services/`** is the only place that talks to Supabase. Components call
  hooks; hooks call services. No `supabase.from(...)` inside a component.
- **`components/ui/`** is generated by the shadcn CLI. Customise by editing the
  file directly — that is the intended model.
- **`lib/`** holds dependency-light helpers and client construction.

## Routing

`createBrowserRouter` in `src/app/router.jsx`. Every route nests inside
`RootLayout`, so the skip link, header, `<main id="main-content">`, and footer
are consistent.

| Path | Component | Status |
|---|---|---|
| `/` | `HomePage` | Hero implemented; sections placeholdered |
| `/collections` | `CollectionsPage` | Placeholder |
| `/collections/:slug` | `CollectionDetailPage` | Placeholder |
| `/products/:slug` | `ProductDetailPage` | Placeholder |
| `/cart` | `CartPage` | Empty state only |
| `/checkout` | `CheckoutPage` | Placeholder — **not operational** |
| `/checkout/payment` | `PaymentPage` | Placeholder — **not operational** |
| `/orders/:id/confirmation` | `OrderConfirmationPage` | Placeholder |
| `/account` | `AccountPage` | Placeholder — no auth |
| `/wishlist` | `WishlistPage` | Empty state only |
| `*` | `NotFoundPage` | Working |

`errorElement` renders `RouteError`, which distinguishes a 404 from a thrown
error. Pages are imported eagerly; add `React.lazy` route splitting once the
real screens grow.

Because this is a SPA, a deep link served by a static host needs a rewrite to
`index.html`. `vite preview` and `vite dev` handle this already.

## State

| Kind | Tool |
|---|---|
| Server data | TanStack Query. Query keys namespaced by feature. |
| URL state | React Router params and search params — filters and pagination belong in the URL so listings are shareable. |
| Local UI state | `useState` / `useReducer`, co-located. |
| Cross-cutting client state (cart) | Not yet chosen. Decide when the cart is built; React Context is sufficient unless profiling says otherwise. |

Query defaults: 60s `staleTime`, 5min `gcTime`, one retry, no refetch on window
focus. The client is created inside `useState` in `providers.jsx` so it is
constructed exactly once.

## Error handling

Three layers:

1. `ErrorBoundary` (`components/shared/error-boundary.jsx`) wraps the whole
   tree and catches render errors. Class component by necessity.
2. `RouteError` handles router-level errors and unmatched URLs.
3. `ErrorState` / `EmptyState` / `LoadingState` handle per-section outcomes.

## Security boundaries

- Only `VITE_`-prefixed variables reach the browser. Everything in the bundle
  is public.
- The Supabase **service-role key bypasses RLS** and must never appear in
  frontend code or a `VITE_` variable. An ESLint `no-restricted-syntax` rule
  blocks reading secret-shaped `import.meta.env` keys.
- Cloudinary's API key and secret are server-side only. No `cloudinary` SDK is
  installed. Uploads require a trusted backend — see `docs/PROJECT_SETUP.md`.
- Row Level Security must be enabled on every table before the frontend reads
  it. No tables exist yet.
